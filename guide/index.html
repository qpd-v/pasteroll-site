Package, copy, carousel, paste

  1. Install Pasteroll. Use Setup on Windows, the archive or .deb on Linux X11, or the GNOME development package on GNOME 46.
  2. Copy something. Pasteroll records text, file lists and pictures unless recording is paused or the source app is excluded.
  3. Open the carousel. Hold CtrlShift and middle-click. On GNOME Wayland, use the setup in GNOME 46.
  4. Paste. Scroll to a clip and click where it should go, or press Enter for the window you came from.

If nothing appears, check that recording is on in the tray or panel menu and that the target window is not excluded.

Windows Setup and the portable folder

Run pasteroll-0.1.0-beta.19-windows-x64-setup.exe. Only for me is the default and needs no administrator rights; For all users uses UAC. The Start menu shortcut is on by default. Desktop shortcut and start at sign-in are off.

To use the portable build, extract pasteroll-0.1.0-beta.19-windows-x64-portable.zip and run pasteroll.exe. The included portable.txt keeps data in the adjacent data folder.

Updating from the tray or a new Setup

From beta.9, the tray menu can offer Download and install when Check for updates is on. The update window shows what changed, downloads only after you confirm, verifies the signed manifest and checksum, installs and restarts. You can also quit Pasteroll and run the new Setup, or replace the files in a portable folder while leaving data alone.

What Windows keeps unless you say otherwise

Use Settings > Apps > Pasteroll. The interactive uninstall asks whether to delete history and settings; the default is to keep them.

SmartScreen

The beta is unsigned. Compare the SHA-256 value, then choose More info, Run anyway.

The X11 archive and .deb need X11 or XWayland

Check the session before installing. Run echo $XDG_SESSION_TYPE; it should print x11. Ubuntu and Fedora often log in to Wayland by default, so choose an Xorg session from the login screen if needed.

One user or all users with the archive

tar xzf pasteroll-0.1.0-beta.19-linux-x86_64.tar.gz
cd pasteroll-0.1.0-beta.19-linux-x86_64
./install.sh
pasteroll run

The installer copies to ~/.local/bin, adds a menu entry and icon, and keeps existing settings. For all users, run sudo ./install.sh --system.

A .deb installs with dpkg

sudo dpkg -i pasteroll_0.1.0-beta.19_amd64.deb

What the Linux uninstall leaves in place

Archive: ./install.sh --uninstall or sudo ./install.sh --system --uninstall. Debian package: sudo dpkg -r pasteroll. These keep history and settings. Remove a portable folder after quitting the app.

Optional: Tesseract enables Extract text, and Zenity or KDialog provides save dialogs. Without a dialog, images save to the Desktop.

GNOME 46 Wayland needs a companion and protocol 4

GNOME 46 only

Other GNOME versions and Wayland compositors are not supported. The app and companion must use protocol 4, and the GNOME .deb replaces the X11 package rather than installing beside it.

  1. Install the GNOME development archive or .deb from Download.
  2. For an archive, run ./install-gnome-companion.sh. Log out and back in, then enable pasteroll@pasteroll.com.
  3. For mouse activation, enable the optional host helper with sudo ./install-input-helper.sh --enable or sudo systemctl enable --now pasteroll-input.service for the Debian package.
  4. Start with pasteroll run --backend gnome. For keyboard-only activation, add --wayland-keyboard and use CtrlShiftSpace.

The helper needs systemd, logind and uinput and supports relative mice with a middle button. Testing has not covered physical helper devices, login or lock screens, suspend, or mixed-DPI layouts. Follow the full GNOME setup guide.

Favorites beyond history limits and a carousel kept open

Favorites are never removed by history limits. Favorite clips also appear as tiles above the list; right-click a tile to paste, unfavorite, or give it a color. The colors live in pin-colors.txt in the data folder.

Rolls are separate collections. Main is the full history and new copies always land there. LEFT and RIGHT are built in on either side; right-click a clip and choose Move to roll, or create a roll from the menu. Settings can hide built-in rolls, add Most used and Images, reorder rolls, and set the rolling keys or tilt-wheel actions.

Keep the carousel open with CtrlK. It stays above other windows while the keyboard and wheel return to the window you are using. The Paste button and favorite tiles paste into the window in front. Mouse multi-paste works while it is pinned.

No Bloat shows only the current clip. The search bar and controls appear when you use them; keyboard features remain available. Switch the look from the tray menu or Settings.

One paste built from several clips

  1. In the Complete look, Ctrl+click each clip you want, or use Ctrl+Shift+click for a range. Ctrl+M turns on keyboard multi-paste.
  2. With multi-paste on, Shift+↓ chooses the clip shown and each one you walk to; Ctrl+arrows add clips; Space chooses the shown clip; CtrlA chooses all.
  3. Click where the text should go, or press Enter. Hold Ctrl while clicking, or press CtrlE, to open join options first.

The join card can separate clips with a new line, space, comma or tab; make a plain, numbered or bulleted list; and change the order. Ctrl+C or right-click Copy puts the joined text on the clipboard without pasting. Pictures are left out. The result enters history as one clip with a badge.

The picture editor and local OCR

Choose an image clip, then hold Ctrl while clicking the desktop or a window. The editor opens with a live preview. A plain click saves the picture on the desktop or pastes it into the target immediately.

  • Outline, crop, resize, rotate, flip, round corners, add a drop shadow or padding, and remove or fill the background.
  • Draw with a pen, soft brush, circle, arrow or text; undo and redo cover the marks.
  • Save a fresh PNG, JPG, WebP or BMP with quality, a name and a folder. The original clip is unchanged.

Extract text uses local OCR. On Linux it requires Tesseract; on Windows it uses the built-in recognizer. OCR accuracy varies, especially with small text in screenshots.

The MCP brain reads only the rolls you share

The agent brain is a local read-only MCP server, off by default. It reads only the rolls you share and sends them to the harness that started it. Pasteroll opens no port and sends nothing itself.

pasteroll brain on
pasteroll brain add Work
pasteroll mcp-config

mcp-config prints the exact entries for Claude Code, Codex and OpenCode. The server exposes four tools: brain_status, brain_read, brain_search and brain_get. It has no tool that writes, copies, pastes or deletes.

What a harness can receive

A harness that reads a clip may send it to its model provider, as if you had pasted it into the chat. Share only a roll you are comfortable giving to that provider. Images are off unless enabled. See MCP privacy.

Windows update paths and manual Linux updates

Windows can update from the tray menu through a signed update window. Linux packages update by hand: download the new archive or .deb, quit the running app, and install it. Your history, key and settings stay in the data folder.

The optional update check is Windows-only, off until you enable it, and reads a short signed note from GitHub. Linux packages do not contact an update service.

When the carousel, paste or history goes wrong

The carousel does not appear

Check that Pasteroll is running, recording is not paused, and another program is not already using Ctrl+Shift+middle-click. On GNOME, confirm the companion is enabled and the backend is gnome.

The clip lands in the window that was active

Pasteroll pastes into the window that was active when the carousel opened. Click the destination once, then reopen the carousel. A terminal may need Ctrl+Shift+V or Shift+Insert; use paste_keys.txt for other apps.

A copied clip does not show up

Check the current filter and search text, the recording pause state, and the app exclusion list. Deleted clips remain in the recycle bin for 30 days unless removed permanently.

A blank or tiny window on Linux

Confirm you are on X11 for the standard package. GNOME Wayland requires GNOME 46 and the matching companion. For mixed-scaling problems, include your desktop, version and monitor layout in a GitHub issue.

Extract text does not appear

Install Tesseract on Linux. Windows uses the built-in recognizer. Try a tighter selection around the text; OCR does not send the image anywhere.

Mouse activation fails on GNOME 46

Check that the helper service is enabled, the mouse has a middle button, and no other remapper owns the device. Then test keyboard mode with --wayland-keyboard to isolate the input path.

Cost, data folders and platform limits

Is Pasteroll free?

Yes. The source is dual-licensed under MIT or Apache-2.0; choose either.

Does Pasteroll send my clipboard anywhere?

No. History is local and encrypted. The optional Windows update check contacts GitHub after you opt in. The optional MCP server shares selected rolls with a harness you start; that harness may send the content to its model provider.

Are password-manager copies recorded?

Copies that password managers mark as sensitive are skipped, and you can exclude programs by name. A clipboard history is still sensitive; keep disk encryption on and set limits you are comfortable with.

Which Linux download fits my session?

Use the X11 archive or .deb for an X11 session. Use GNOME 46 development packages only for the experimental native Wayland backend. The two Debian packages are alternatives.

Where does Pasteroll store data?

Windows: %LOCALAPPDATA%\Pasteroll. Linux: ~/.local/share/pasteroll. A portable.txt beside the program uses an adjacent data folder. History and settings survive normal upgrades and uninstalls unless you choose to delete them.

Is there a macOS build?

No. The download page lists the Windows, Linux X11 and GNOME 46 packages.
